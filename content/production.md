# Production plan — Staalfront campaigns

Scope: two campaigns × 10 missions, 20 briefings, 8 voiced characters + system voice, 20 new maps. Target engine: Staalfront's own engine (B1) with the trigger model from WP10.1. The mission documents use the primitives of that model (zones, points, teams, timers, variables, messages); `CONVENTIONS.md` defines the document contract that engine data is generated from. Where a mission needs a primitive WP10.1–10.3 do not provide, §3a lists it as "needs to be added to WP10.x" and §7 lists the fallback. §2a maps this plan onto PLAN.md (phases 10, 12 and 15, milestone M2).

## 1. Pipeline per mission

```
mission doc (md) ──► map sketch (png) ──► map file + trigger script ──► smoke test ──► playtest ──► tuning
       ▲                                                                              │
       └─────────────────── changes always go back into the mission doc ◄─────────────┘
```

Rules:
1. The mission doc is the source of truth. Nothing exists in the map script that is not in the doc, and vice versa (`scripts/validate.py` checks the doc side).
2. Zones/points/objects keep their doc names in the engine (`Z_`, `P_`, `OBJ_`, `T_`, `TR_`, `MSG_`).
3. Each mission gets a `missions/<code>-map.png` sketch before map work starts. Minimum content: zones outlined, points marked, ore fields, start positions, entry routes, map size in cells.
4. Test scenario list (section K) is executed as a checklist on every build of that mission.

## 3. Engine data to build

- **Roles**: every row in `units.md` as a unit/structure definition (WP3.1 units, WP6.1 buildings; PLAN §5 rule 6: data in RON). Mission-only objects (ferry, rail_spur, automated_gun, …) are structures with no build option. Speeds are in cells per second; the sim runs at 20 ticks per second with `Fx::ONE` = 1 cell (B12), so speed 0.7 is 0.035 cells per tick. `sf_data` converts once at load time and must check that every speed in `units.md` is representable in `Fx` without drift.
- **Faction restrictions**: build lists per campaign step from the tech-tree table in `units.md`; a campaign-progress flag per mission gates the list.
- **Trigger primitives needed**: collected from all 20 docs and mapped onto WP10.1–10.3 in §3a. Seven kinds have no counterpart in PLAN or in the groundwork documents (terrain state change, hit-point override, inspect-without-capture, conditional immunity, ownership transfer, count-in-zone with a duration, area damage); a number of smaller gaps are marked too. All carry the words "needs to be added to WP10.x".
- **AI profiles**: `defends`, `attacks`, `harasses` as defined in `units.md`; team orders are explicit so the AI profile only governs base rebuilding and harvesting.
- **Campaign flags**: `completed_<code>`, `evidence_<code>`, `civilian_harm_F2-M02`, `reveal_F2` (WP10.5 campaign structure). Flags change one briefing line at most; never block progression.

## 4. Briefings and audio

- The scripts are 6–10 lines each (45–75 s, v3): each briefing states the situation, the primary objective, the constraint that makes it hard, and one line that foreshadows the twist without revealing it. Conventions: one cue spelling per character as in `cast.md`; a speaker is named in the action lines unless the cue carries (V.O.) or (O.S.); transitions other than "… TO:" start with ">" (`> FADE OUT.`). `scripts/validate.py` checks all three.
- In-mission messages: all MSG_ lines in the 20 docs are the voice-over list. Export them to a single sheet (`scripts/export_messages.py`) for the recording session.
- Voice cast: Elian, Mira, Rusk, Sava, Lenka, Petrov (recurring); Venn, Kovac (one-off); Operations (system). Nine actors or doubled roles; Venn/Kovac/Operations can be doubled.
- **Human actors and the planned voice tool.** PLAN §10 lists "text-to-speech placeholder" for voices now and voice actors as the real thing. `docs/cutscene-inspiration.md` §4 proposes the voice tool as WP12.7 (offline text-to-speech, English per B8, a WAV per line, lip-sync through WP12.3; a candidate engine is Piper, MIT, with the licence of each voice checked and recorded in `assets/LICENSES.md`). It is not in PLAN.md yet. Proposal: the tool voices the briefings and `voiceover.csv` from the first cartoon briefing on (M2), so the pipeline works without actors; the voice descriptions in `cast.md` are the brief for both. Human actors replace the tool per character, with the same line identifiers, once Tijmen has cast them (P6). Whether the tool is good enough for final voices is judged by ear.
- Music: three states (briefing, tension, combat) plus two stingers (twist, win/loss). Twist stinger plays on every `twist_revealed` trigger.

## 5. Art

- Map tilesets: North Ridge (snow/farmland), The Vale (forest/river), Coastworks (docks/industry), Glass Orchard (greenhouses/channels), Black Basin (foundry/concrete). Five tilesets, reused across both campaigns.
- Unit silhouettes per `world.md` §3. Decoy_emplacement must be pixel-identical to defence_tower from the enemy's side and subtly different for the owner.
- Briefing portraits: poses listed in `cast.md`.

## 6. Testing

1. **Doc validation** — `python3 -I content/scripts/validate.py` on every commit: references resolve, roles exist in `units.md`, required objectives have a completing trigger, win and loss triggers present, every MSG speaker and every briefing cue is in `cast.md`, every speaker is in the room or marked (V.O.)/(O.S.), transitions carry ">". The tech tree per mission is not checked automatically.
2. **Smoke test** per mission — the section K test scenario, scripted where the engine allows (force-trigger TR_ codes).
3. **Playtest** — one tester per difficulty band; record completion time vs. target length (±25 % acceptable), number of attempts, where players got stuck. Missions missing the window twice get a tuning pass.
4. **Difficulty curve** — plot attempts per mission; a lighter mission must follow each 4+ mission (F1-M07 after M06, F2-M07 after M06 are the intended breathers).
